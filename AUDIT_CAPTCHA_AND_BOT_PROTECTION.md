## 🚨 Главный вывод — картина архитектуры была неверной

В `captcha_summary.md` предполагалось: CAPTCHA живёт в `@F_unified_bot`, а
`@F_chatsBot` — только для рассылок. **Это не так.**

Реальность, подтверждённая кодом и боевой базой данных:

- **`unified_bot`** (тот, что был первым прислан) вообще не содержит кода
  для CAPTCHA — ни обработчика новых участников, ни ограничений, ни базы
  сессий. Он занимается только OneMessage / Каруселью / Репостером.
- **CAPTCHA полностью реализована и активно работает внутри `F_chatsBot`**
  (`app/captcha/service.py`, `handler.py`, `generator.py`, `keyboards.py`).
  Она уже мьютит новых участников, показывает эмодзи-проверку в ЛС,
  снимает ограничения при правильном ответе — и уже записывает всех,
  кто прошёл проверку, в базу для рассылки (`users.source_chat_id`).
- Сообщения от **`F_notice`**, которые ты видел на скриншоте ("🛡 Пройти
  проверку" со стрелкой, автоудаление через 10 сек) — по формату это
  один в один `_send_group_prompt()` из `F_chatsBot`. Похоже, это тот же
  движок, просто отображается под другим именем/инстансом бота.

**Значит, ничего доизобретать не нужно.** Задача — не писать четвёртого
бота, а разобраться с тем, что уже работает, и закрыть конкретную дыру.

### Что это означает

1. ✅ **CAPTCHA реально блокирует спам-постинг.** 98%+ ботов не может
   написать ни слова в группу — они физически не доходят до ответа на
   вопрос (ноль банов за неверные ответы = боты даже не пытаются угадать,
   они просто не открывают ЛС бота).
2. ❌ **Но она не решает твою настоящую проблему.** Атака — это не попытка
   получить доступ к постингу. Это just массовое вступление и (предположительно)
   последующий самостоятельный выход ботов. CAPTCHA в принципе не может
   этому помешать, потому что:
   - Telegram Bot API **не позволяет боту запретить пользователю вступить**
     в публичную группу (это was бы противоречило самой идее публичности).
   - Telegram Bot API **не позволяет боту запретить пользователю выйти**
     из группы.
   - Мьют (`restrict_chat_member`) блокирует только отправку сообщений —
     сам факт "вступил/покинул" всё равно происходит и попадает в
     "Недавние действия", даже если пользователь ни разу не написал.

3. 🐛 **Найден реальный баг**, усугубляющий проблему: после истечения
   таймера (`_timer_task` в `service.py`) сессия просто помечалась
   `expired`, а мьют **никогда не снимался и пользователь никогда не
   удалялся**. Итог — тысячи замьюченных "зависших" аккаунтов месяцами
   висели в списке участников группы. Когда они (или скрипт атакующего)
   в какой-то момент выходят — это выглядит как ещё одна волна
   "вступлений/выходов", хотя де-факто это просто уборка мусора, который
   годами копился из-за отсутствующей автоочистки.

## 🛠️ Что уже сделано в этой сессии

### Патч: `f_chatsbot_patch/app/captcha/service.py`

Один точечный фикс — по истечении времени на CAPTCHA пользователь теперь
**реально удаляется** из группы (кик с `until_date` +10 минут, не
перманентный бан — через 10 минут он сможет вступить и попробовать снова).
Подробности и инструкция по установке — `f_chatsbot_patch/PATCH_NOTES.md`.

Это не решает саму волну вступлений, но:
- не даёт замьюченным ботам копиться в списке участников навсегда;
- ускоряет их уход (не через недели самостоятельного выхода, а через
  10 минут после провала проверки) — уборка происходит предсказуемо
  и контролируемо ботом, а не хаотично.

### Убран лишний черновик

В прошлой итерации я по неверной картине архитектуры начал писать
отдельный `unified_bot_with_captcha` с нуля. Это было бы **дублирующей**,
конфликтующей логикой (два бота одновременно мьютят/снимают мьют с одного
пользователя — гонка условий, баги). Черновик удалён — используем то,
что уже работает в `F_chatsBot`.

## ❌ Что не может починить ни один бот (важно понимать честно)

Ключевой вывод для управления ожиданиями: у Telegram Bot API есть
структурные ограничения, которые никаким кодом не обойти:

| Проблема | Может ли бот это решить |
|---|---|
| Запретить боту написать спам в группе | ✅ Да — мьют/CAPTCHA (уже работает) |
| Запретить боту вступить в публичную группу | ❌ Нет — Bot API не даёт такого метода для публичных групп |
| Запретить боту выйти из группы | ❌ Нет — выход инициирует сам пользователь/скрипт |
| Ускорить удаление уже отфильтрованных ботов | ✅ Да — патч из этой сессии |
| Скрыть волну "вступил/покинул" из "Недавних действий" | ❌ Нет — это системный лог Telegram, не то, чем управляет бот |

### Что реально может снизить риск для группы

1. **Встроенный "Агрессивный анти-спам" Telegram** (Настройки группы →
   Администраторы → Анти-спам). Это нативный ML-фильтр самого Telegram,
   заточенный именно под такие паттерны ботоферм — в отличие от бота, он
   видит сигналы на уровне самого Telegram (IP, паттерны аккаунтов и т.д.),
   которые недоступны через Bot API. **Рекомендую включить, если ещё не
   включён** — это первое, что стоит проверить.
2. **Report как spam/scam на сами боты-аккаунты** — если видно конкретные
   ID (а они есть в `datewell.db`), можно пожаловаться на них в Telegram
   напрямую через `@notoscam` / `Report` в клиенте — это не остановит
   атаку мгновенно, но снижает шанс, что именно твою группу(!) заметят
   как источник проблем, а не атакующих ботов.
3. **`telegramcleaner.py`** (тот, что был прислан первым) — держи его под
   рукой для ручной чистки, если где-то накопится "хвост" старых ботов,
   не пойманных CAPTCHA (например, вступивших до её включения).
