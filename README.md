# CRM — сеть массажных салонов и сауна

Самописная CRM для сети из 4 салонов и 1 сауны: контроль звонков на номер
каждого объекта, ИИ-расшифровка и разбор разговора, проверка скрипта по
чек-листу, определение администратора по голосу приветствия, пропущенные и
перезвоны, база клиентов с визитами и рейтингом, страница гостей для
администраторов объектов, отчёты для владельца. Тот же стек и принципы, что
и в CRM журнала «ЕКБ ГИД».

## Стек и деплой

Node.js, Express 4, better-sqlite3 (SQLite), JWT в cookie, bcryptjs, xlsx
(экспорт в Excel). Один `server.js` + `public/index.html` (SPA), порт 3002
(отдельный от журнальной CRM инстанс). Все ключи (OpenAI, UIS) — в базе,
вводятся через «Настройки», `.env` не используется (кроме `JWT_SECRET`).

## Модули

```
db.js               → схема SQLite и первичная инициализация (объекты, администраторы,
                       клиенты, звонки, чек-листы, записи, визиты)
auth.js             → JWT-логин в cookie, requireAuth/requireAdmin
lib.js              → нормализация телефона, эффективный чек-лист объекта, доступ
telephony.js        → приём звонков UIS по 5 номерам, пропущенные, привязка перезвонов
ai-processing.js    → транскрибация + разбор: администратор, тройной чек-лист,
                       резюме/разбор/советы по удержанию, исход, извлечение записи
call-out.js         → клик-звонок через UIS Call API (отложено, код готов)
reports.js          → 4 вида HTML-отчётов (администратор/объект/сеть/клиенты)
server.js           → REST API и точка входа
public/index.html   → фронтенд SPA (владелец) + мобильная страница «Гости» (staff)
```

## Модель данных

- **Объекты (`salons`)** — 4 салона + 1 сауна, у каждого один номер UIS, тип
  (`salon`/`sauna`), режим чек-листа (`template`/`custom`). Удаление из
  интерфейса = архивация (`active=0`): номер освобождается, история звонков
  и клиентов сохраняется.
- **Администраторы (`admins`)** — отдельно от учётных записей: существуют как
  метка для ИИ даже без логина. Привязаны ровно к одному объекту. Статус
  `confirmed`/`unconfirmed` — новое имя, услышанное ИИ и не найденное в
  справочнике, создаёт неподтверждённую запись; в «Администраторы» /
  «Дашборд» её можно подтвердить, переименовать или удалить (отклонить).
  Опциональный `user_id` — логин для страницы «Гости».
- **Чек-листы (`checklist_items` + `checklist_overrides`)** — два шаблона
  («Салон», «Сауна»). Объект в режиме `template` наследует активные пункты
  своего шаблона (кроме отключённых override'ом) + свои добавки; в режиме
  `custom` — только свой приватный список (снимок снимается автоматически
  при отвязке от шаблона).
- **Звонки (`calls`)** — направление in/out, статус (`new/processing/done/
  error/missed/skipped`), поля пропущенных/перезвонов (`callback_call_id`,
  `callback_status`, `callback_minutes`), тройной чек-лист
  (`checklist_results` JSON: yes/partial/no + цитата), исход (`booking/
  interest/callback/refusal/spam`), советы по удержанию.
- **Клиенты (`clients`)** — склейка по нормализованному телефону по всей
  сети; имя извлекает ИИ из разговора.
- **Записи (`bookings`)** — создаются автоматически, когда ИИ находит в
  разговоре подтверждённую запись (дата/время).
- **Визиты (`visits`)** — факт «дошёл/не дошёл»: либо привязаны к записи
  (отметка на странице «Гости»), либо самостоятельные (гость без звонка).
- **Закрытие дня (`day_closures`)** — отметка администратора объекта, что
  все записи на день размечены; незакрытые дни видны на дашборде владельца.

## Пайплайн звонка

1. `telephony.js` раз в `poll_interval_sec` опрашивает UIS по номеру каждого
   активного объекта (один опрос покрывает все номера сети).
2. Входящий без ответа → статус `missed`, ИИ не запускается — только учёт.
   Система ищет последующий исходящий с номера этого же объекта на номер
   клиента: находит — связывает пару и считает `callback_status`
   (`on_time` ≤ окна, `late` — позже, с точным числом минут). Не находит в
   течение окна — временно помечает `none` («не перезвонили»); если перезвон
   всё же случится позже, статус будет пересчитан на `late` при поступлении.
3. Отвеченный входящий или исходящий (включая перезвон) сразу уходит в
   `ai-processing.js`: аудио → `gpt-4o-mini-transcribe` → текст → один запрос
   в LLM с контекстом объекта, его справочником администраторов и его
   чек-листом → определение администратора (с учётом падежей/уменьшительных
   имён, автосоздание неподтверждённого при новом имени), чек-лист
   ✅/⚠️/❌ с цитатами, резюме/разбор/советы по удержанию, исход,
   при подтверждённой записи — авто-создание `booking`.
4. Клиент карточки объекта видит результат сразу; «Обработать заново» —
   после правки чек-листа, ключа или ручной коррекции администратора.
5. На странице «Гости» администратор объекта отмечает «Пришёл/Не пришёл» по
   записям на день и может добавить визит без звонка; в конце дня —
   «Закрыть день».

## Доступы

Два уровня, без промежуточных ролей:

- **Владелец** (`role=admin`) — все объекты, звонки, расшифровки, чек-листы,
  разборы ИИ, пропущенные/перезвоны, база клиентов и рейтинг, отчёты,
  настройки и ключи.
- **Администратор объекта** (`role=staff`, привязан через `admins.user_id`
  к ровно одному объекту) — только страница «Гости» своего объекта: список
  записей на день, отметки «Пришёл/Не пришёл», добавление визита без звонка,
  закрытие дня. Никакого доступа к звонкам, чек-листам, другим объектам или
  аналитике по себе.

## Настройка

1. `npm install`, задать `JWT_SECRET` в окружении.
2. `npm start` (или pm2: `pm2 start server.js --name crm-salons`).
3. Первый вход: `admin` / `admin123` (или `ADMIN_DEFAULT_PASSWORD`) — сменить
   пароль сразу.
4. «Настройки»: ключ OpenAI, доступ UIS (Data API — обязательно; Call API —
   опционально, для клик-звонка), окно перезвона (по умолчанию 5 мин).
5. «Салоны»: завести VIP / Рай / Жара / НУАР (тип «салон») и Алиса (тип
   «сауна»), внести номера UIS каждого.
6. «Администраторы»: завести известный состав вручную (имя + объект);
   остальных доучтёт ИИ из приветствий как неподтверждённых — подтвердить
   на дашборде.
7. При необходимости — свои правки стартовых чек-листов «Салон»/«Сауна».
8. Выдать логины для страницы «Гости» тем администраторам, кто должен
   отмечать визиты (раздел «Администраторы» → «Выдать доступ»).

## Отличия и упрощения относительно резюме ТЗ

- **UIS API**: конкретные названия полей ответа `get.calls_report`
  (`direction`, `is_lost`, `contact_phone_number` и т.п.) не проверены на
  живом кабинете — тот же статус, что и в исходном проекте («доступ ещё не
  открыт»). Как только доступ откроется, поля/маппинг в `telephony.js`
  может понадобиться скорректировать под фактический ответ API.
- **Итог чек-листа «N из M»**: посчитан как `✅=1 + ⚠️=0.5`, округление не
  применяется — в интерфейсе и отчётах показывается и дробный балл, и
  раздельные счётчики ✅/⚠️/❌.
- **Извлечение даты записи** (`booking.when_iso`) — ИИ переводит фразу вида
  «завтра в 15:00» в ISO-дату по собственному пониманию контекста; при
  неуверенности дата остаётся пустой, но текст фразы сохраняется всегда.
- **Привязка перезвона к пропущенному** ищется в окне 48 часов по
  нормализованному номеру клиента в рамках одного объекта — этого достаточно
  для типичного бытового сценария, но не является полноценным call-tracking
  (см. известную слепую зону ниже).
- **Известная слепая зона (как и в ТЗ)**: перезвон виден системе, только
  если администратор звонит с виртуального номера объекта через приложение
  UIS. Перезвон с личного мобильного не попадёт в UIS-отчёт и будет выглядеть
  как «не перезвонили». Решение — клик-звонок (модуль `call-out.js` уже
  есть, но по ТЗ отложен).
- **Импорт Excel** не делался (не было в ТЗ) — только экспорт звонков и
  клиентов (`/api/export/calls.xlsx`, `/api/export/clients.xlsx`).
- **Ежедневный автобэкап БД** не реализован в коде этой сессии (в ТЗ
  указан как унаследованный принцип) — рекомендуется настроить cron с
  `sqlite3 data/salons.db ".backup ..."` или копированием файла на VPS.

## Заметка по безопасности зависимостей

`npm audit` показывает high severity для пакета `xlsx` (prototype pollution /
ReDoS в парсере SheetJS, фикса под npm нет). В этом проекте `xlsx`
используется только на запись — экспорт собственных данных CRM в `.xlsx`
(`XLSX.utils.json_to_sheet` + `XLSX.write`), парсинг чужих файлов нигде не
делается, поэтому уязвимость (эксплуатируется через открытие вредоносного
файла) не применима к этому сценарию использования. Если в будущем появится
импорт `.xlsx` от пользователей — этот пакет для парсинга использовать не
стоит.

## Стоимость ИИ (ориентировочно)

Расшифровка + анализ звонка: ~1 ₽. Отчёт: ~0,2 ₽. Пропущенные без ответа —
бесплатно (чистый учёт, ИИ не вызывается). Курс расчёта настраивается в
«Настройки» (по умолчанию 90 ₽/$), точные суммы — там же, счётчики
сегодня/всего.
