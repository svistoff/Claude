# CRM — сеть массажных салонов

Самописная CRM по образцу «ЕКБ ГИД»: несколько салонов, по одному телефонному
номеру на салон, приём и транскрибация звонков, ИИ-разбор (кто ответил, что
сказал, что улучшить) и HTML-отчёты. Тот же стек и тот же принцип работы,
что и в исходном проекте.

## Стек

Node.js, Express 4, better-sqlite3 (SQLite), JWT в cookie, bcryptjs. Один
`server.js` + `public/index.html` (SPA), порт 3001. Все ключи (OpenAI, UIS)
хранятся в базе и вводятся через раздел «Настройки» в интерфейсе —
`.env`-файл с секретами не используется (кроме `JWT_SECRET`, см. ниже).

## Модули

```
db.js               → схема SQLite и первичная инициализация
auth.js             → JWT-логин в cookie, middleware requireAuth/requireAdmin
lib.js              → общие хелперы (эффективный чек-лист салона, доступ к салону)
telephony.js        → приём звонков из UIS Data API (get.calls_report) по номеру салона
ai-processing.js    → транскрибация (gpt-4o-mini-transcribe) + ИИ-разбор (кто ответил,
                       чек-лист, резюме/сильные-слабые стороны/рекомендации)
call-out.js         → клик-звонок через UIS Call API (start.simple_call)
reports.js          → HTML-отчёты по салону и по сотруднику (кнопка печати в PDF)
server.js           → REST API и точка входа
public/index.html   → фронтенд SPA
```

## Модель данных (кратко)

- **Салоны** — CRUD только у админа: название, адрес, один телефон (номер UIS),
  можно удалить вместе со всей историей звонков.
- **Сотрудники** — логин/пароль/роль (`admin`/`staff`), может быть привязан
  сразу к нескольким салонам (таблица `user_salons`). Поле `phone` — номер в
  приложении UIS, нужен для клик-звонка.
- **Чек-лист** — общий шаблон пунктов (`checklist_items` с `salon_id = NULL`)
  + пункты, добавленные только для конкретного салона, + возможность отключить
  конкретный общий пункт для одного салона (`checklist_overrides`).
- **Звонки** — по одному номеру на салон: дата, длительность, ответили/нет,
  ссылка на запись в UIS (не хранится физически — только на время обработки),
  расшифровка, кто ответил (распознанное имя + сопоставление с сотрудником
  салона), результаты чек-листа, резюме/сильные-слабые стороны/рекомендации.

## Как работает пайплайн звонка

1. `telephony.js` каждые N секунд опрашивает UIS по номеру каждого активного
   салона и создаёт запись в `calls` для новых звонков.
2. Если звонок отвечен (`is_answered`), сразу запускается `ai-processing.js`:
   аудио скачивается во временный буфер → `gpt-4o-mini-transcribe` → текст →
   отправляется в LLM вместе со списком сотрудников салона и его чек-листом →
   получаем определение сотрудника, отметки по чек-листу, резюме и разбор.
3. Результат сохраняется в карточке звонка, доступной сотрудникам этого
   салона и админу.
4. В любой момент можно нажать «Обработать заново» — например, после правки
   чек-листа или ключа API.

## Настройка

1. `npm install`
2. Задайте `JWT_SECRET` в переменных окружения (иначе используется дефолтный —
   для продакшена обязательно переопределить).
3. Запуск: `npm start` (или через pm2: `pm2 start server.js --name crm-salons`).
4. При первом запуске создаётся админ `admin` / `admin123` (или пароль из
   `ADMIN_DEFAULT_PASSWORD`) — смените пароль сразу после входа.
5. В интерфейсе: «Настройки» → укажите ключ OpenAI и данные доступа UIS
   (Data API — для приёма звонков, при необходимости Call API — для
   клик-звонка). Как и в исходном проекте, UIS требует добавить IP сервера в
   whitelist (Аккаунт → Правила и настройки безопасности → API).
6. Добавьте салоны (раздел «Салоны»), сотрудников с привязкой к салонам
   (раздел «Сотрудники»), при необходимости — свои пункты чек-листа
   (раздел «Чек-лист»).

## Отличия от исходной CRM «ЕКБ ГИД»

- Вместо общей базы контрагентов — сеть салонов с разделением данных: у
  каждого салона свой номер, свои звонки, свой набор сотрудников и (при
  необходимости) свои пункты чек-листа поверх общего шаблона.
- Оценка исхода звонка (`deal/interest/callback/refusal`) заменена на
  настраиваемый чек-лист конкретных пунктов, которые задаёт руководитель, —
  ИИ отмечает выполнение каждого пункта с цитатой-подтверждением.
- Добавлено распознавание того, кто из сотрудников ответил на звонок, по
  фразе представления в начале разговора, с сопоставлением со справочником
  сотрудников салона.
- Модуль закрепления контрагентов за менеджерами не переносился — в CRM
  салонов нет отдельной клиентской базы, только журнал звонков по номеру
  каждого салона.

## Стоимость (ориентировочно, по тарифам из исходного проекта)

- Транскрибация: ~$0.003/мин разговора.
- Анализ звонка (определение сотрудника + чек-лист + разбор): доли рубля за
  звонок, точная сумма считается по фактическому расходу токенов и видна в
  «Настройки» → счётчики расходов (сегодня/всего, в $ и ₽ по настраиваемому
  курсу).
