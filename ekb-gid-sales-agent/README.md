# EKB GID Sales Agent — MVP (Путь А: скиллы внутри Claude)

Ассистент **для менеджера** ЕКБ ГИД. Приходит холодный запрос («скиньте прайс»),
менеджер вставляет ссылку на соцсети клиента + текст сообщения — агент исследует
бизнес, определяет вероятные «боли», подбирает форматы ЕКБ ГИД по актуальному
прайсу и готовит: **разбор лида + 3 варианта + готовый персональный ответ +
следующий шаг**. Отправляет менеджер — агент сам клиенту не пишет.

Это Путь А: не отдельное приложение, а набор Claude Skills + база знаний,
которые работают **внутри Claude / Claude Cowork**. Быстрый запуск, вся логика
живёт в текстовых файлах, которые легко править.

## Структура

```
ekb-gid-sales-agent/
├── skills/
│   ├── inbound-sales/SKILL.md     # главный: обработка входящего обращения
│   └── company-research/SKILL.md  # переиспользуемый: research по ссылке
└── knowledge/                     # «мозг» и источник истины (правьте здесь)
    ├── pricing.md      # ЕДИНСТВЕННЫЙ источник цен
    ├── playbook.md     # тип бизнеса → боли → форматы → зацепки (главный файл)
    ├── sales-rules.md  # тон общения, запреты, механика ответа
    ├── products.md     # продукты и логика подбора
    ├── editorial.md    # рубрики журнала (для идей)
    ├── audience.md     # аудитория (без выдуманных цифр)
    ├── ekb-gid.md      # о проекте
    └── objections.md   # логика работы с возражениями
```

## Как пользоваться (в Claude Code / Cowork)

1. Открой этот проект в Claude.
2. Дай агенту вводные, например:

   > Обработай входящее обращение (skill inbound-sales).
   > Ссылка: https://instagram.com/example_trainer
   > Сообщение клиента: «Здравствуйте! Скиньте, пожалуйста, прайс на рекламу».
   > Что уже известно: пишет фитнес-тренер, ведёт групповые занятия.

3. Агент прочитает `knowledge/`, исследует компанию и вернёт карточку менеджеру
   с готовым ответом. Менеджер проверяет и отправляет сам.

## Что менеджеру нужно поддерживать

- **`pricing.md`** — держать цены актуальными. Всё, чего тут нет, агент помечает
  «цена требует уточнения» и не выдумывает.
- **`playbook.md`** — дополнять типами бизнеса и болями по мере опыта. Это
  главный актив: чем точнее плейбук, тем полезнее агент.

## Принципы (зашиты в скиллы)

- Думаем от **задачи клиента**, а не от прайса: ЗАДАЧА → ИДЕЯ → ФОРМАТ → ЦЕНА.
- Персонализация — на **реальной** зацепке из соцсетей, а не на выдумке.
- Разделяем факт / наблюдение / гипотезу; гипотезу не выдаём за факт.
- Никаких обещаний результата, скидок и бартера «на автомате» — решает человек.
- Цены — только из `pricing.md`.
